# Проверка web-чата Омни

Откройте https://moodrost.github.io/omni-widget-test/ и вставьте целиком код
`<script …></script>` из вкладки **«Виджет на сайт»** нужного канала.
Нажмите **«Проверить подключение»**, затем **«Загрузить виджет»**.
Редактировать репозиторий для смены канала не нужно.

Код сохраняется только в localStorage этого браузера. После обновления страницы
он восстанавливается, но запросы и загрузка SDK автоматически не запускаются.
Кнопка **«Сменить подключение»** очищает сохранённый код и перезагружает страницу,
чтобы удалить старый SDK и его обработчики без вызова API отзыва сессии.

Поддерживаются штатные HTTPS-коды Target AI: `src`, `data-key`,
`data-channel-id`, необязательные `data-api-url` и `data-light`.
Если API не задан, используется origin скрипта + `/api/v1`, как в SDK.
Вставленный HTML не исполняется; скрипт создаётся из проверенных параметров
только после нажатия «Загрузить виджет». Inline JavaScript и неизвестные
атрибуты отклоняются. Секреты, API-токены и пароли сюда не нужны.

Для работы разрешите `https://moodrost.github.io` в настройках виджета.
HTTP 404 от config API означает, что сервер не нашёл активный виджет для
переданного ключа и канала. Проверьте включение канала и вставьте свежий код.
Сайт сам не включает канал и не меняет его маршрутизацию.

Проверка подключения делает только GET config. Загрузка окна ещё не доказывает,
что агент отвечает: для этого пользователь должен отправить сообщение и
проверить ответ и диалог в Омни.

## Проверка изменений

Запустите `python -m http.server 8765 --bind 127.0.0.1` из корня репозитория.
Откройте `http://127.0.0.1:8765/tests/regression.html` и нажмите «Запустить».
Проверки используют подставные ответы и SDK: обращения к рабочим сервисам
и создание диалогов не выполняются.
